# Uploads go straight to storage by signed URL; originals are stored once per workspace by content hash

`packages/storage` talks the S3 API with aws4fetch: Cloudflare R2 when deployed, RustFS in Docker Compose locally and in CI (MinIO no longer publishes images). The browser hashes a file, asks the API for an upload, and PUTs the bytes to a signed URL that is good for five minutes, one key, one content type and one size. The API then records the asset after hashing the stored bytes and reading the image header; bytes that don't match their hash or aren't a PNG, JPEG or WebP are deleted and refused. Originals live at `workspaces/<workspace>/originals/<sha256>`, so the same file is stored once per workspace, and every brand that uploads it gets its own asset row, so assets never cross brands. (They were under `orgs/<org>/` until ADR-0011.)

Reads go through the API too: it signs a short-lived GET URL after the workspace and brand checks, and the web app passes the bytes on to the editor, so browsers never hold storage addresses or credentials. The editor and Node renders load the same bytes by asset id and decode them with CanvasKit, so an image renders identically in both. Resized copies, when we need them, are images we make and store as their own objects; nothing is resized on the fly.
